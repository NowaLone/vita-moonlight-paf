# Промпт для исходного чата: поиск ПК на Main

Реализуй согласованный перенос поиска ПК на главный экран Vita Moonlight PAF.
Полностью удали страницу Search PC и кнопку Search PCs. Поиск должен работать
автоматически в фоне с обновлением каждые 5 секунд, без блокировки UI и без
модальных окон поиска.

Работай по текущим AGENTS.md, проектному skill и Ponytail full. Сначала прочитай
docs/UI.md и docs/WIFI_BACKGROUND_SEARCH_RESEARCH.md. Последний файл содержит
проверенную цепочку официального поиска AP в Settings, адреса ELF и пределы
выводов. Не повторяй широкий обзор системных модулей и не подменяй реализацию
общим предложением.

## Что установлено по официальным Wi-Fi Settings

- На одной странице page_wifi_main расположены отдельные сохранённые
  link_saved_ap_* и найденные btn_scanned_ap_*. Обнаружение и сохранение — разные
  состояния. Фиксированные лимиты Sony и высота строк 70 px не являются
  требованиями к Moonlight.
- Sony планирует поиск одноразовым PAF-таймером 0x01000001, получает результаты
  через асинхронные NetCtl callbacks и после обработки цикла заново ставит timeout
  с аргументом 5000.0. Это пауза после завершения, а не запуск пересекающихся
  сканирований строго по настенным часам. Отдельный timeout 1000.0 обслуживает
  состояние подключения.
- Поиск AP использует локальный 32x32 PAF BusyIndicator в строке Access Points;
  это не модальное окно. Текст поиска показывается лишь при пустых сохранённом
  и найденном списках и включённом Wi-Fi. Для Moonlight сохраняем тихий фон и
  нынешнюю политику статического empty-state; новые spinner/статусы не требуются.
- Sony обновляет именованные строки и снимает таймеры при уходе со страницы.
  Точный алгоритм сохранения фокуса и срок исчезновения AP не установлены.
  Не представляй свои решения по этим вопросам как подтверждённую логику Sony.
- Зелёная сфера Sony показывает состояние подключения, а не факт обнаружения.
  В Moonlight сохраняем существующий смысл индикатора: свежая проверка TCP
  доступности выбранного GameStream endpoint.

## Требуемое поведение интерфейса

1. Main содержит один список: сохранённые ПК сверху в устойчивом порядке,
   временно найденные несохранённые ПК ниже. Не добавляй разделители, подписи
   «Найден в сети», счётчики поиска и сообщения о каждом обновлении.
2. Индикатор доступности слева показывается ТОЛЬКО у сохранённых ПК. У временных
   строк его нет вообще — ни зелёного, ни тусклого. Не передавай временные ПК в
   проверку доступности. Сохрани одинаковые позиции имени, адреса и значка ПК,
   чтобы сохранение не сдвигало содержимое строки. Представление задай в CXML;
   используй существующий подход выбора шаблонов, не двигай геометрию из C++.
3. Удали Search PCs из нижней панели. Оставь нативный Add PC с SceImeDialog и
   существующий уголок Delete/Settings. Не меняй высоту строк Main и остальную
   геометрию ради копирования Wi-Fi Settings.
4. Запускай обнаружение при готовности активного Main. Повторяй mDNS-запросы с
   интервалом 5 секунд в единственном принадлежащем backend worker; не создавай
   новый поток/PAF job для каждого запроса. Не считай существующий десятисекундный
   одноразовый поиск готовой реализацией этого требования. Используй монотонное
   время; задержанный цикл не должен порождать очередь догоняющих запусков.
5. Список остаётся интерактивным. При неизменившемся снимке не трогай его структуру;
   при изменениях обновляй нужные строки. Сохраняй прокрутку и фокус по идентичности
   ПК. Обновление текстуры доступности не должно удалять ячейки и менять row tokens.
   Если исчезла строка с фокусом, переходи к ближайшей оставшейся, не перескакивай
   без необходимости в начало. Проверь реальные доступные PAF API перед выбором
   способа обновления, не выдумывай методы по аналогии с другими UI.
6. Не очищай временные результаты на старте каждого цикла. Одно пропущенное mDNS
   объявление не должно вызывать мигание списка. Определи и задокументируй простую
   политику устаревания по последнему наблюдению. Ранее предложенные 15 секунд —
   возможный выбор для Moonlight, а не установленный Sony TTL. Ошибку поиска или
   отменённый цикл не выдавай за подтверждённый пустой результат. Сохранённые ПК
   автоматически не удаляются.
7. Убирай дубли между сохранёнными и найденными. Учитывай UUID, когда он реально
   известен, затем пригодные существующие идентификаторы/адрес и порт. Нынешний
   mDNS не предоставляет UUID — не придумывай его и не начинай авторизацию ради
   фонового сопоставления. Одинаковое имя не является достаточной идентичностью.
8. Выбор найденного ПК фиксирует снимок выбранного хоста, сохраняет его и разрешает
   каноническую запись из полного сохранённого списка по адресу/порту, как нынешний
   Search. Затем использует обычное подключение Main → PIN или Apps. Простое
   обнаружение ничего не пишет на диск. Ошибки сохранения обрабатывай существующим
   нативным диалогом; не продолжай подключение после неудачного сохранения.
9. Режим Delete работает только с сохранёнными ПК: временные строки на это время
   скрываются; Select All, доступность Delete и checkbox учитывают только сохранённые.
   После выхода общий список восстанавливается. Удалённый сохранённый ПК может снова
   появиться как найденный без индикатора; удаление не является сетевой блокировкой.
10. После Apps, отмены PIN или ошибки pairing возвращайся на Main; убери все
    ответвления восстановления callback через Search и текст «Use Search PCs».

## Фон, владение и границы

- Это явно разрешённое исключение из правила модальных foreground-операций:
  только обнаружение на Main работает в фоне. Обычные Connect/Apps/launch, PIN,
  нативные ошибки и их последовательность остаются прежними.
- При подключении, IME, OptionMenu/Settings, режиме Delete, уходе с Main или
  приостановке приложения прекращай планирование и запрашивай отмену. При возврате
  запускай поиск заново, когда Main инициализирован и действительно активен.
- Нельзя ожидать завершения сетевого worker на PAF-потоке. Раздели запрос остановки
  и освобождение завершённого worker; повторный старт не должен пересекаться с
  прежним. Перед конфликтующей операцией заверши освобождение ресурсов вне UI-потока.
  Не оставляй нынешний блокирующий legacy_host_discovery_stop() на пути UI.
- Публикуй согласованные снимки результатов с корректной синхронизацией и поколением
  поиска; UI меняй только через MoonlightApp main-thread dispatch. Отбрасывай
  запоздалые события отменённого поколения и callback устаревших строк. Не копируй
  изменяемый worker-массив без защиты и не направляй события скрытого Main в Apps/PIN.
- Discovery остаётся сервисом/backend-функцией. Не переноси mDNS в page_main.cpp,
  не меняй протокол, форматы хранения и механизм доверия. Фоновое обнаружение и
  существующие проверки доступности сохранённых ПК имеют разные задачи и интервалы;
  пятёрка секунд относится к обнаружению.
- Ошибки именно фонового поиска — log-only через vita_debug_log(), без окон,
  inline-прогресса и спама каждые 5 секунд. Освобождай сокеты и worker при завершении
  приложения. Не добавляй файловое логирование и частые логи на кадр.

## Завершение и проверка

Полностью убери page_search.cpp/.h, её CMake/CXML-ресурсы и неиспользуемые строки,
callback-ветки и зависимости. Сохрани общие шаблоны/сервисы, которые ещё используются.
Обнови docs/UI.md, актуальные описания README/AGENTS и затронутые source-checks;
исторические свидетельства не переписывай как результаты нового интерфейса.

Добавь минимальные содержательные non-build проверки: повтор через 5 секунд без
пересечения workers, отмена/возврат/устаревший результат, стабильный неизменившийся
список, дубли и одинаковые имена, переход временного ПК в сохранённый, индикатор и
Delete только у сохранённых, выбор ПК при обновлении, возврат Apps/PIN на Main.
Используй текущие tests/README.md и подход проверки реального исходного кода.

Не запускай сборку, компиляцию CXML, CMake configure, Make, упаковку или deployment.
Проверь diff и применимые non-build checks, затем сразу создай коммит каждого
завершённого логического изменения по standing authorization. Не делай push.
В отчёте раздели выполненные source checks и ожидаемую проверку сборкой/на Vita:
фокус/скроллинг, отзывчивость при поиске и остановке, появление/исчезновение ПК,
повторное подключение, Delete/IME/Settings и отсутствие поиска во время стрима.
